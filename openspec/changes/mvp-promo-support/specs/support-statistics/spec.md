# Spec Delta

## Purpose

Capability определяет проверяемую семантику обязательных метрик поддержки и обеспечивает их детерминированный расчёт по сохранённому состоянию без повторного обращения к LLM.

## ADDED Requirements

### Requirement: Provisional метрика bot resolved
До уточнения менеджером единицей `bot resolved` MUST считаться входящее сообщение участника, полностью обработанное ботом без создания обращения. Mixed request и сообщение, приведшее к эскалации, MUST NOT учитываться как `bot resolved`.

#### Scenario: Полностью автоматический ответ учтён
- **GIVEN** для входящего сообщения сохранён grounded-ответ
- **AND** обращение для сообщения не создано
- **WHEN** рассчитывается статистика
- **THEN** счётчик `bot resolved` увеличивается на одну единицу

#### Scenario: Mixed request не учтён как bot resolved
- **GIVEN** бот ответил на известную часть сообщения и создал обращение для оставшейся части
- **WHEN** рассчитывается статистика
- **THEN** сообщение не включается в `bot resolved`

### Requirement: Provisional метрика escalated
До уточнения менеджером единицей `escalated` MUST считаться созданное обращение, независимо от числа сообщений в его истории. Повторная обработка update или job MUST NOT увеличивать метрику.

#### Scenario: Созданное обращение учтено один раз
- **GIVEN** для участника создано обращение
- **WHEN** рассчитывается статистика
- **THEN** `escalated` увеличивается на одну единицу
- **AND** дополнительные сообщения в этом обращении не увеличивают показатель

### Requirement: Provisional среднее время ответа оператора
До уточнения менеджером response time MUST рассчитываться от времени создания ticket до времени первого сохранённого ответа оператора. Обращения без ответа оператора MUST NOT входить в среднее.

#### Scenario: Ticket с первым ответом включён в average
- **GIVEN** обращение создано в известный момент
- **AND** первый ответ оператора сохранён позднее
- **WHEN** рассчитывается среднее время ответа
- **THEN** для обращения используется разница между этими двумя моментами

#### Scenario: Ticket без ответа исключён из average
- **GIVEN** у обращения нет сохранённого ответа оператора
- **WHEN** рассчитывается среднее время ответа
- **THEN** обращение не влияет на числитель и знаменатель среднего

### Requirement: Детерминированный расчёт
Все обязательные метрики MUST вычисляться только из сохранённых сообщений, решений и обращений. Просмотр статистики MUST NOT вызывать LLM или изменять учитываемое состояние.

#### Scenario: Statistics from persisted state
- **GIVEN** в PostgreSQL сохранён набор bot-resolved сообщений, обращений и ответов оператора
- **WHEN** оператор открывает статистику повторно без изменения данных
- **THEN** система показывает те же значения всех трёх метрик
- **AND** внешние AI и Telegram API не вызываются
